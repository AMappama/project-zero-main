名单对不上时，先对三把钥匙

过期 VIP 不是「服务结束了」。重启会把你刚写的样本清掉。

保险柜要三把钥匙一起转

过期 VIP 不是一张存好的表。它是一次查询。少一把钥匙，人就不会出现在那一栏。红娘把过期会员领进自己的服务库之后，当前服务人换成这位红娘，人离开过期名单。

1

有完成的实例

状态是完成，不是失效。退费走失效，不进这张名单。

2

关单四项齐全

已通过的关单上，是否同意、原因、关单人、关单前服务人都不许空。

3

现在没人领着

不能还有有效的服务归属。也不能有「关单后领取」的销售或邀约。

成交时留下、开启前就有的销售 / 邀约归属，不算这次领取。它们不把人从过期 VIP 里拿走。

钥匙缺一，函数直接说不

代码 
  const completed = (await instancesOfMember(tx, memberId)).some((row) => row.status === "完成");
  if (!completed) return false;
  const approved = await approvedClose(tx, memberId);
  if (!approved || approved.consent == null || !approved.reason || approved.closedBy == null || approved.servicePersonId == null) {
    return false;
  }
白话

这位会员有没有任何一本护照是「完成」。函数叫 isOverdueMember。

没有完成的，一定不是过期 VIP。

再找已经通过的关单申请。

申请不存在，或是否同意、原因、关单人、关单前服务人有一个空着，都不算。

直接否决。后面还要再查服务归属和关单后领取。

这把钥匙检查结束。

💡
名单是问句，不是抽屉

服务库问的是：当前服务人是不是我，状态是不是待启用、启用中或暂停。处理中问的是：申请还没走完吗。条件变了，刷新就变。不要让 AI 再造一张「过期池」表。

重启像把排练厅连夜清空

开发时每次 npm run dev 都会 重置库表，再用种子铺开同一天的样本。你下午点过的确认，晚上重启就不见了。这不是没保存，是程序故意清空。

代码 
const { crm, pool } = await openFulfillment({ reset: true });
await seedWorkbench(crm);

跟 AI 卡住时，用这几句把它拉回来

1
空名单先问权限和查询条件

林晓看不到审核，是权限裁剪。过期 VIP 缺一把钥匙，人就不会出现。不要先怀疑前端没渲染。

2
手改身份会被触发器拒绝

要改会员类型，就改服务实例，让同一次事务去回写缓存。不要 UPDATE members.member_type。

3
一审、草稿、到期函都不改护照结局

一审只推进申请。草稿不是推荐。到期函插入一行，不关单。实例变成完成，只发生在关单二审通过。

✦
下一步可以让 AI 做的，只有一件明确的事

推荐补写仍是四组套姓名的句子。若要接模型，保持规则：只填空项，不覆盖已写内容，占位理由可以替换。别的账本规则先别一起改。
