开启要过四道门

付清、合同、服务人、开始日。少一张，人就停在待启用。

登机口不看心情，只看四张牌

机场不会因为你「看起来像要飞」就放行。开启服务也只看四项，外加一个租户开关。不检查实名。

付

订单

付款状态得是 payable 或 paid。未付清，缺口写「订单」。

合

合同

contract_check_status 必须等于 1，也就是审核通过。

人

服务人

会员名下要有一条还有效的服务归属。没有就叫「缺服务人」。

日

计划开始日

计划开始日不能晚于「今天」。今天是演示日，不是墙上的日历。

自动指定服务人时按门店角色排队：先红娘 matchmanager，再店长，再总监。三个角色都没有，就不开启。落到店长或总监名下的，首页例外里标成高优，等人换成红娘。

白话

准备一个缺口清单。这段在 openServiceTx。

没有订单，或钱还没到 payable / paid，记下「订单」。

有订单但合同不是审核通过，记下「合同」。

订单根本不存在就到此为止，不再往下看。

去查这位会员现在的服务归属。

没有有效服务人，记下「缺服务人」。

计划开始日还在演示日之后，记下「计划开始日」。

读这个租户的三个开关。

系统想自动开、但开关关着，记下「确认开启」。等人来点同一次开启。

四项都齐、实例还是待启用，才会写成启用中：写入起止和四类总量，已用为 0，成熟度记为新升级，并记下是谁开的、当时四项长什么样。

门开了，往出站口塞一张明信片

代码 
async function readSettings(tx: Tx, tenantId: number): Promise<Settings> {
  const settingsRow = await firstRow(
    tx.select().from(tenantSettings).where(eq(tenantSettings.tenantId, tenantId)).limit(1),
  );
  if (!settingsRow) return { autoStart: true, loveDraft: false, compatClear: true };
  return {
    autoStart: settingsRow.autoStartService === 1,
    loveDraft: settingsRow.autoDraftCloseOnInLove === 1,
    compatClear: settingsRow.compatClearDealOwnership === 1,
  };
}
白话

读某个租户的开关。

去设置表找这一行。

条件是租户编号相同，只要一行。

查询结束。

没有配置行：自动开启开着，恋爱不自动起草关单，开启时清理成交归属开着。

有配置就按表里的 0 和 1 翻译成是否。

1 才是自动开启。

1 才是恋爱时起草关单。起草了也不自动审核。

1 才在开启时停用销售 / 邀约归属，避免和在服归属并存。

交回三个开关。

💡
开关是行为，不是文案

跟 AI 说「关掉自动开启」时，指的是 auto_start_service。人仍调用同一次 openService，只是系统不再自己开。不要让它新写一套开启函数。
