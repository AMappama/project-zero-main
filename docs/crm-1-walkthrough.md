# 红娘 CRM 走查：谁点、写哪张表、会员屏幕看到什么

按新履约库里的动作，一行一条。谁点，以工作台上的按钮和接口权限为准：林晓只有红娘权限，苏衡是红娘加审核人，没有单独的审核人账号。会员屏幕指会员页。那一页展示算出来的身份、成熟度列、当前服务人、服务实例的状态和起止与四类次数、已经确认的推荐、约会、人工小记。待确认的推荐草稿不在会员页上，在工作台的待判断里。到期函和申请会随会员接口返回，会员页没有把它们画出来。

身份每次都按这个人全部服务实例重算，不在下面逐行重复公式。`members.member_type` 只在改实例的同一次事务里回写，人不能在会员页上改它。

| 动作 | 谁点 | 写入 | 会员屏幕看到什么 |
| --- | --- | --- | --- |
| 指定服务人 | 红娘。缺服务人或待换人时，按钮是「指定服务人」或「换成红娘」 | 只改 `service_ownerships` 这一行：当前服务人，来源「指定」，有效。不写销售单、邀约单、小记 | 当前服务人变成这一位。身份和实例状态这一下不变。页面接着会跑一轮系统自动，那一轮可能再写别的行，见下 |
| 系统写下默认服务人 | 没有按钮。系统自动时，订单和合同已够、还没有有效服务人，就按门店 matchmanager、店长、总监的顺序写一位 | `service_ownerships`，来源「默认」。三个角色都没有则不写 | 会员页出现这位服务人。落到店长或总监时，工作台例外写「待换成红娘」，不是会员页上的另一个状态 |
| 确认开启 | 红娘。只有缺口只剩「租户关掉了自动开启」时，才有「确认开启」 | `service_instances` 从待启用改为启用中，写入计划开始、开始、结束、总结束、四类总量，已用为 0，并记下开启人和四项快照。`members.maturity` 写成「新升级」。兼容开关开时，停用该会员仍有效的 `deal_assignments`。插入一条 `outbox_events`，类型 `ServiceStarted`。回写身份缓存 | 这一单变成启用中，能看到起止和四类「已用/总量」。身份变为 VIP。成熟度显示「新升级」。没有旧式开启按钮 |
| 系统开启 | 没有按钮。四项都满足且租户允许自动开时，由系统自动执行，写入和确认开启相同，开启人记成 system | 同上 | 同上。关了自动开就不会偷偷变成启用中 |
| 准备推荐草稿 | 红娘登录时，系统给这位红娘服务库里、还没有待确认草稿的会员各准备一条。客人取库内另一个会员。也可以走红娘接口 | 只插入 `tasks`：种类「推荐草稿」，状态「待确认」。不写 `recommendations` | 会员页的推荐列表仍是空的，或只有已确认的。待确认出现在工作台待判断，文案写明确认之后才写入推荐事实 |
| 确认推荐 | 红娘，待判断里确认那一份草稿 | 插入 `recommendations`（嘉宾、进度文字、理由、亮点、隐瞒点）。若带了草稿，把该 `tasks` 改为「已确认」。不改成熟度，不回写身份，不写小记 | 会员页推荐里出现这位嘉宾。成熟度不变 |
| 确认约会 | 红娘，约会页「确认一次约会」。对象要有会员编号，或有外部姓名 | 插入 `meetings`。结果和反馈可以先空着 | 会员页约会里多一场：日期、地点、对象；结果是「还没填」 |
| 填写见面结果 | 红娘，到点未填时按钮「填写见面结果」。选项是已见面、未见面、取消、恋爱，反馈可空 | 只更新这一行 `meetings` 的结果和反馈。不改成熟度，不改实例，不写小记 | 这一场约会的结果不再是「还没填」。恋爱不会在这一下把实例改成完成 |
| 发起暂停 | 红娘，「发起暂停」。只有启用中可以发起 | 插入 `applications`：类型暂停，状态待审，带起止和原因。不改实例 | 会员页这一单仍是启用中，结束日不变。工作台审核出现「暂停待审」 |
| 发起赠送 | 红娘，「发起赠送」。启用中或暂停可以发起。要有天数，或某一类次数加多少 | 插入 `applications`：类型赠送，状态待审。不改实例 | 会员页的结束日、总量、状态都不变。审核出现「赠送待审」 |
| 发起关单 | 红娘，「提前关单」，或在「已恋爱，建议关单」上自己发起。启用中或暂停可以发起 | 插入 `applications`：类型关单，状态待审，原因用提交的文字，是否同意可先空着。不改实例 | 会员页实例状态不变。审核出现「关单一审」 |
| 系统起草关单 | 没有按钮。总结束日已到，且这单还没有未结束的关单，系统插入待审关单，原因「到期」。租户把恋爱开关打开时，约会结果为恋爱也会插入，原因「恋爱」。不自动审核 | 插入 `applications`，状态待审，是否同意为空。不改实例 | 会员页实例不变。待判断里出现「到期起草的关单」或「已恋爱起草的关单」 |
| 系统写下关单建议 | 没有按钮。约会结果已是恋爱、开关仍关、总结束日还没到。不建关单申请 | 插入 `tasks`：种类「关单建议」，状态「待确认」，原因「恋爱」 | 会员页不变。待判断写「已恋爱，建议关单」，并说明没有代填是否同意。红娘若要关，再点发起关单 |
| 记下是否同意 | 红娘。起草的关单还没记下是否同意时，有同意和不同意两个按钮 | 只改这张关单 `applications` 的是否同意。待审和待二审才能改 | 会员页实例不变。该申请的说明变成用户同意或不同意 |
| 关单一审 | 审核人。林晓没有审核权限 | 通过：这张申请改为待二审。驳回：改为驳回。都不改实例，不停归属 | 会员页实例不变。通过后审核子页从关单一审到关单二审 |
| 关单二审通过 | 审核人。必须已有是否同意、原因、关单人、当时的服务人 | 申请改为通过，写上关单人和当时的服务人。`service_instances` 改为完成。当前服务归属停用。`members.maturity` 写成「已关单」。回写身份缓存。不写过期池，不写诚意库，不写小记 | 这一单状态变成完成。若没有别的启用中、暂停或待启用，身份变成过期 VIP。人离开原红娘的服务库，出现在过期 VIP 查询里。成熟度显示「已关单」 |
| 关单二审驳回 | 审核人 | 只把申请改为驳回 | 会员页实例保持原样 |
| 暂停审核通过 | 审核人，一次 | 申请改为通过，并记下剩余服务月。实例改为暂停。成熟度写成「暂停」。回写身份缓存。结束日和总结束日不动 | 这一单变成暂停，起止日期和通过前相同。身份变为暂停。这一档高于另一笔只是待启用 |
| 暂停审核驳回 | 审核人 | 只把申请改为驳回 | 实例仍是启用中 |
| 赠送审核通过 | 审核人，一次 | 申请改为通过，payload 记下改前改后。实例只延长结束日或总结束日，或增加某一类总量。不改状态，不改已用，不回写身份 | 会员页能看到新的结束日或更大的总量，已用仍是原来的数，状态不变 |
| 赠送审核驳回 | 审核人 | 只把申请改为驳回 | 结束日和总量不动 |
| 恢复 | 红娘在暂停结束日之前点「提前恢复」。到了暂停结束日由系统自动恢复。两次写入相同 | 实例回到启用中。新的结束日是恢复日加上申请上的剩余月；总结束日若更晚则保留更晚的那天。申请记下恢复日。回写身份缓存。不改成熟度列 | 实例回到启用中，结束日按剩余月重算。身份按实例重算，启用中则为 VIP。成熟度列仍显示「暂停」，这一列没有在恢复时改回去 |
| 写下到期函 | 没有每日发送按钮。总结束日已到时系统插一行；也可以走接口。同一订单已有函则不再插 | 只插入 `close_vip_contract`。不改实例，不代替关单 | 会员页不展示这封函。实例状态和起止不动 |
| 更新到期函状态 | 没有页面按钮，只有接口 | 只改 `close_vip_contract` 的状态和备注 | 会员页仍不展示。实例不动 |
| 退费完成 | 没有页面按钮，只有接口 | `order_facts` 的退款记为完成。实例改为失效。若当前有效归属就是这一单，则停用归属。回写身份缓存。不把失效写成完成，不改成熟度 | 这一单变成失效。若没有启用中、暂停、待启用，且这是订单时间最新的一笔，身份变成退费 |
| 红娘领取 | 红娘，过期 VIP 页「红娘领取」。人必须已在过期名单上 | `service_ownerships` 改为有效，来源「红娘领取」。不新建实例 | 过期名单不再列出此人。此人出现在这位红娘的服务库。实例仍是完成，所以会员页这一单还是完成；身份仍按实例算 |
| 销售领取 | 过期 VIP 页「销售领取」。接口不检查红娘或审核人权限 | 插入 `deal_assignments`，角色销售，来源「关单后领取」。不写服务归属 | 人离开过期 VIP。不进入服务库。会员页的服务实例仍是完成 |
| 邀约领取 | 过期 VIP 页「邀约领取」。权限同上 | 插入 `deal_assignments`，角色邀约，来源「关单后领取」 | 同上，不进入服务库 |
| 记下这次联系 | 红娘，会员页「记下这次联系」 | 只插入 `notes` | 人工小记多一行。调配、开启、关单不会自动出现在这里 |
| 记得出站事件已消费 | 没有页面按钮 | 只把 `outbox_events` 里这条 `ServiceStarted` 的消费时间填上 | 会员页没有这一行 |

系统自动那一轮还会做的事，都已经拆在上表：默认服务人、开启、到点恢复、到期函、起草关单或关单建议、以及调用方递来的推荐草稿。它不审核，不确认推荐，不填写见面结果。
